# 五连块匣 · PENTAPACK

把五连块填进一只匣子，一格不留。

这个仓的核心主张只有一句：**每一关的"只有解"是证明出来的，难度是量出来的，
玩家看到的每个数字都能被机器复算。**

- 每一关的匣子形状与那 k 块，来自一次随机的装箱过程 —— 所以它天生有解；
- 装箱之后用 dancing links（Algorithm X）穷举这个匣的全部铺法，
  **只留下解数恰好为 1 的那些**，因此"填满就算完成"在这只匣里不是宽容，而是等价；
- 难度不是形容词：`推理深度` 是一个只用两条推理规则的求解器**实际进入过的最深假设层数**，
  关卡档位由 (块数 k, 推理深度) 这一对被机器查出来，界面上那两个字也走同一条函数；
- 步数是一个经济学：`落子 1 步、取回 1 步、拖动已上的块 1 步、旋转/镜像 0 步、被拒绝的落子 0 步`，
  所以一关的最少步数恰为 k，星级量的是你在 k 之上浪费了多少。

## 玩法

屏幕左边是匣子和待置块，右边是进度。把待置区的块拖进匣子，压叠或出框会被弹回（不算一步）；
块放完且与烘焙解答一致，卡片就上来。

| 操作 | 效果 |
| --- | --- |
| 拖动 | 从待置区取块放入匣子，或把已放下的块挪去别处 —— 都是一步 |
| 拖回待置区 | 取回那块，一步 |
| 双击匣上的块 | 原地顺时针转 90°，0 步；转不过去就不转 |
| 右键 / 长按 0.48 s | 镜像，0 步 |
| `f` | 镜像最后动过的那块 |
| `u` / `h` / `r` | 撤销 / 提示 / 倒回本匣 |

提示是查表不是搜索：它读的是随包发布的那条解答，所以它永远不与证明打架。

## 关卡

`js/data/lots.js` 由 `tools/bake.mjs` 生成，30 关 = 5 档 × 6 关，共 900 格匣面。
`depth` 是烘焙时**测量**到的推理深度，不是设定值：

| 档位 | 名称 | 块数 k | 深度窗口 | 这 6 关实测深度（按关卡序） |
| --- | --- | --- | --- | --- |
| taster | 上手匣 | 4 | 0–1 | 1,1,0,1,1,0 |
| easy | 常匣 | 5 | 1–3 | 2,2,2,2,1,2 |
| mid | 中匣 | 6 | 2–4 | 3,4,3,2,3,4 |
| hard | 硬匣 | 7 | 3–5 | 3,4,3,5,3,4 |
| iron | 铁匣 | 8 | 4–7 | 4,5,6,4,7,4 |

另有两种生成内容：**每日匣**（种子就是日期，全设备同一关，档位按年在五档间轮转）与
**随机匣**（链接里的 seed 决定这一关）。链接形式：

```
#/lot/taster-01        指定关卡        #/daily              今天那一关
#/daily/2026-03-04     指定日期        #/random/<seed>      无尽匣
#/random/<seed>?band=hard             固定档位
```

解锁只升不降，`best[id].moves` 只降不升，两条都在写入方 `js/core/storage.js` 里强制执行。

## 难度为什么可以信

两条推理规则（`js/core/logic.js`）：

- **R1** 某一格只剩一个还能盖住它的块 —— 定；
- **R2** 某个块只剩一个还放得下的位置 —— 定。

两条都不起作用而匣子没满时，求解器必须**猜**：取候选最少的空格，假设一种铺法，递归一层。
`推理深度 k` 就是它为了收完工真正进过的那条路线上的最深假设层数。

诚实条款：这个 k 属于上面这对规则，不属于谜题本身。加第三条规则（"若这块放这里，X 格就无解了"）
全屋的 k 都会掉。规则集写在代码里、写在 DESIGN 里、也由 `test/logic.test.mjs` 钉住；
**规则一改，关卡必须重新烘焙**，因为包里每个数字都是关于这套规则的陈述。

生成流水线的四道闸（`tools/bake.mjs`）：装箱构造 → DLX 后验解数 == 1 → 推理深度落进档位窗口 →
**把序列化后的那一行重新读回来再证一遍**。第四道是关键：它让"发布出去的数被验证过"这句话
说的是发布出去的那几个字节。`test/library.test.mjs` 在 CI 里跑同一套复证，所以手改
`js/data/lots.js` 里任何一个 par 都会把构建弄红。

求解器本身对着公开数字校过：十二块五连块铺满矩形（铺法按矩形对称取商）——

| 矩形 | 本仓算出 | 公开值 | DLX 展开节点 |
| --- | --- | --- | --- |
| 3×20 | 2 | 2 | 34,783 |
| 4×15 | 368 | 368 | 922,440 |
| 5×12 | 1010 | 1010 | 2,507,589 |
| 6×10 | 2339 | 2339 | 4,050,281 |

`node tools/proof.mjs` 就是上面这张表（4 anchors fail: 0）。姿态表 `js/core/pieces.js` 自己也是
断言过的：12 块互不重复、每块 5 格四连通、逐块姿态数 F8 I2 L8 N8 P8 T4 U8 V4 W4 X1 Y8 Z4，
合计 **63** 个 fixed 姿态，且 rot⁴=1、mirror²=1、mirror∘rot∘mirror=rot³（D₄）。

## 本地运行

零依赖、零构建、零二进制资产（`package.json` 的 `dependencies` 与 `devDependencies` 都是 `{}`，
由 `tools/check.mjs` 断言）。

```bash
npm run dev      # node server.cjs 5197 → http://127.0.0.1:5197/
npm test         # 分层自检 + 9 个 node suite
npm run verify   # 全套门禁：node suite + 真实 headless Chrome 打真实事件
npm run proof    # 上面那张公开锚点表（约 33 s 的真搜索）
npm run bake     # 重新生成关卡表（PER_BAND=8 可放大）
```

浏览器门禁用本仓专属端口 **web 5197 / devtools 9357**；开跑前先拒绝被占用的端口，
跑完再确认 Chrome 真的退了 —— 端口撞车在这里不是麻烦，而是**假绿**。

## 已知边界

- 界面只在 8×8 及以下的烘焙匣与生成匣上被真事件验证过；更大盘面走 `#/random/<seed>` 也受
  `make.js` 的窗口约束。
- `推理深度` 是这套两规则求解器的实现测量，不是组合学下界；DESIGN §9 记了它曾怎么被写错。
- 完成判定不现场跑 DLX：它比对烘焙解答（DESIGN §2.4），依赖"解数 = 1"这条被复证的性质。
